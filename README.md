# bb cinema

**Watch movies and series together, with synchronized playback.**

bb cinema is a self-hosted app for two people to watch together from separate devices. Choose something from a shared library, join the same lobby, and play, pause or seek from either device. Playback stays coordinated when someone buffers or reconnects. You can also watch alone.

Search TMDB, save titles to a shared wishlist, and see which ones are available in your library. Local media stays on the host Mac and streams through Jellyfin; viewers do not need to transfer the whole file first.

Both profiles share **one library, one wishlist and one playback room**. This developer preview supports two participants. Hosting currently requires macOS, Bun, Node and a separate Jellyfin installation; there is no one-click installer yet.

## Viewing devices

View from a desktop, laptop, tablet or phone using a modern browser. The player uses native HLS where available and HLS.js otherwise. Automated coverage currently includes Chromium and WebKit; real-device and Firefox acceptance remain pending. iPad Safari is one viewing example, not a requirement. The current host setup is macOS-only.

## Run locally

Requires Bun 1.3.13+, Node 20.9+ (Node 24 recommended), and native Jellyfin **12.0.0**, the latest stable release verified for this implementation. The app rejects prereleases, versions below 10.11.10 and an installed version that differs from `JELLYFIN_VERSION`.

```sh
bun install --frozen-lockfile
bun run build
bun run start
```

In a second terminal, from the same directory:

```sh
bun run setup
```

Open the private, single-use host setup link printed by that command. The link grants host administration and expires in ten minutes; keep it on the host device. Set the Jellyfin address/version, enter two distinct non-administrator playback accounts, name both profiles, and optionally add a TMDB read access token. The form verifies connections before saving. Select a profile to enter the shared library.

In Settings → Invitations & devices, create a viewer invitation. Viewer devices can select either profile but cannot administer the installation. Invitations last 24 hours and one use; paired sessions last 30 days. The host can revoke other devices from Settings.

Use Settings → Connections → Edit connections to update service credentials. Blank password fields keep existing passwords; TMDB offers keep, replace and remove actions. Saved settings and a failed library refresh are reported separately.

No `.env` editing is needed for local setup with the default ports. For a separate data location, different ports, or a private HTTPS origin, copy `.env.example` to `.env`, set its permissions to 600 and configure those advanced values before startup. Saved service credentials live in the local private SQLite database and take precedence over the corresponding environment values. Backups now include them and must remain private.

Without TMDB, the local library and playback work; catalogue discovery requires enabling TMDB. The current server integration requires Jellyfin on the same machine. See [deployment](docs/DEPLOYMENT.md) for permissions, private remote access, login startup and recovery.

Both Bun (`127.0.0.1:3000`) and Next.js (`127.0.0.1:3001`) bind to loopback. Use only port 3000 as the application endpoint. Next.js is an internal UI process. Production does not require serverless hosting or a cloud upload.

## Verification

```sh
bun run typecheck
bun test tests
bun run build
bunx playwright install chromium webkit
bun run test:e2e
```

Browser tests use two separate cookie contexts, mock TMDB/Jellyfin services, and a synthetic H.264/AAC test clip generated by FFmpeg. Install `ffmpeg` to run them. Test services are **only** launched by the test harness, bind to localhost, and use a disposable database; there is no production demo/auth bypass. Playwright WebKit is useful regression coverage but does not substitute for real-device Safari.

See [implementation decisions](docs/IMPLEMENTATION.md), [private macOS deployment](docs/DEPLOYMENT.md), [protocol and security](docs/SECURITY.md), and [acceptance checklist](docs/ACCEPTANCE.md). Real hardware/network acceptance remains a separate required step. Automated test results cannot establish remote-network throughput, VideoToolbox performance, or device-specific full-screen behavior.

## Commands

| Command                                       | Purpose                                                       |
| --------------------------------------------- | ------------------------------------------------------------- |
| `bun run dev` / `bun run start`               | Start both persistent processes on localhost                  |
| `bun run db:migrate`                          | Apply committed SQL migrations                                |
| `bun run db:backup`                           | Create a consistent SQLite backup with `VACUUM INTO`          |
| `bun run setup` / `bun run invite partner`    | Generate one-time pairing codes                               |
| `bun run check:jellyfin` / `check:tmdb`       | Validate service connectivity                                 |
| Settings → Test this connection               | Download an authenticated, uncached 8 MB bitrate sample       |
| `bun run tailscale:serve` / `tailscale:check` | Explicitly configure / inspect private Serve                  |
| `bun run awake`                               | Keep the powered Mac awake until Ctrl-C                       |
| `bun run launchagent`                         | Generate a native LaunchAgent for review; does not install it |

## Scope

Movies and TV episodes, shared library and wishlist, discovery, named profiles, resume/reset progress, lobby, synchronized controls, buffering coordination and reconnect are implemented. Auto quality chooses an initial resolution and bitrate from a short connection sample; it does not continuously adapt. SRT/VTT text subtitles switch independently; burned-in subtitles require a new stream.

This is a developer preview, not a packaged end-user release. Initial startup uses command-line tools; service configuration and viewer invitations use the UI.
