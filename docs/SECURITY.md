# Security and playback protocol

## Boundaries

Tailscale is the network boundary; cookie authentication is an additional boundary. The Bun gateway validates the Host header against the configured application origin. Every mutation requires the exact Origin and a session-specific CSRF header; redeeming invitations requires exact Origin and is rate limited. WebSocket upgrades require the same origin, a valid cookie and CSRF token in the subprotocol list. Do not log headers or WebSocket subprotocols in another proxy.

Session IDs contain 256 random bits and only SHA-256 digests are stored in SQLite. HTTP-only, SameSite=Strict cookies expire after 30 days and use Secure for HTTPS. This is opaque server-side session authentication, rather than a self-contained signed cookie. Single-use invitation codes expire in 24 hours. Invitations authorize trusted devices to select either of the two named profiles. Creating another device session does not revoke existing sessions. Profile selection rotates the session CSRF token and closes that session’s old socket; it does not disconnect other devices. Profiles are convenience identities, not a security boundary between the two trusted people. A host device can revoke other sessions in Settings → Invitations & devices. Signing out revokes the current session. Live sockets re-check expiry/revocation; stream requests also authenticate. Only one active browser tab controls each identity; a second tab replaces the first and the first does not reconnect indefinitely.

Jellyfin signs in separately as restricted owner/partner playback users. Neither may be an administrator, delete media or manage subtitles. No administrator API key is supported. Disable downloads and nonessential user permissions in Jellyfin as documented in DEPLOYMENT. Browser routes do not proxy general Jellyfin APIs and never accept local filesystem paths. Jellyfin alone reads the configured folders. Manual matching only modifies a database relation, not a media file.

Media URLs are short-lived opaque resource IDs bound to the authenticated session. HLS playlist references are recursively rewritten, including quoted URI attributes and segments. References must stay on the configured localhost Jellyfin origin and under the selected video's path. Absolute third-party references and encoded traversal/separators fail closed. Range requests stream without buffering the entire movie. Upstream Authorization headers and query strings are never returned to the browser. Native HLS sends the same-origin session cookie. A cached manifest or stolen resource ID does not work without the matching session.

TMDB credentials remain server-side. Movie metadata uses upstream max-age/s-maxage and no-store/no-cache directives. Artwork is proxied through the Mac, with browser caching governed by the upstream headers; the MVP does not maintain an offline image cache. HTML, API and playback responses do not use public caches. Only known error summaries are logged, without request headers, exception dumps or full URLs.

The UI requires inline Next.js bootstrap scripts; its current CSP permits inline scripts and development eval, but restricts resources to this origin and disallows framing. A future nonce-based production CSP is worthwhile. This is not intended for public hosting. Do not add analytics or third-party scripts.

## Room

One room, two fixed participants. Zod validates inbound commands. Commands are handled synchronously by the Bun event loop; the server assigns monotonically increasing versions, and clients ignore older snapshots. Media selection resets readiness and position. A normal play requires both participants connected, ready and not buffering. Either may explicitly choose Watch alone once their own player is ready and not buffering. Solo mode is visibly labelled and ignores the other viewer's readiness/buffering. Watch together pauses, clears solo mode and requires both viewers to mark ready again. When both become ready while in solo mode, playback pauses before shared watching resumes. Solo mode clears when the solo viewer leaves the player, disconnects, or the server restarts; pausing alone does not clear it.

Clients ping every two seconds, retaining a window of RTT/clock-offset samples and using the lowest-RTT sample to reduce asymmetric jitter. At 250 ms intervals, expected position is computed from the server anchor. Drift under 500 ms gets a 0.98/1.02 speed correction (a small dead band prevents needless rate changes); larger drift triggers a seek. Local volume never enters room state. Programmatic video events are suppressed so native controls do not echo state changes back as user commands.

Buffering beyond 1.2 seconds pauses the room at the authoritative position. After every connected/ready viewer recovers, the room resumes only if it was paused by buffering. A deliberate pause cancels automatic resume. Socket closure pauses immediately; silent disconnects are detected within 15 seconds and pause playback. Reconnect retrieves a full snapshot and negotiates a fresh stream; the viewer must activate playback again if Safari requires it. The local player pauses while disconnected. Saved room state is checkpointed every five seconds and always restores paused, with both participants unready. A restart creates a new version and requires user readiness again.

Jellyfin is asked for per-client playback information with a conservative Safari-compatible profile. MP4/H.264/AAC and capability-detected HEVC can play directly when within budget. Otherwise Jellyfin provides HLS remux/transcode. Text subtitles use Jellyfin-converted WebVTT; image/ASS subtitles ask Jellyfin to burn in. The player uses native Safari HLS before HLS.js. Audio and burned-in subtitle changes renegotiate playback and reset readiness. SRT/VTT text track changes preserve the video stream and readiness. Playback progress/stop reports are sent to Jellyfin; transcode stop targets the prior play session. Validate subtitle and audio combinations against your actual media using the physical acceptance checklist.

## Host capability and configuration

Host permission is a database-backed device-session capability independent of the selected display profile. Migration 006 defaults all existing sessions and invitations to viewer-only. A local `bun run setup` command creates a ten-minute, single-use host authorization link. No HTTP endpoint issues host invitations. Ordinary invitations always grant viewing access only, even when an unexpected privilege field is submitted. Origin/CSRF and capability checks protect all host routes.

The host form accepts only the configured local Jellyfin origin policy and fixed service fields; it cannot change listener addresses or read arbitrary files. Credentials are stored in the mode-600 SQLite database. They are not encrypted at rest beyond OS/disk protection; protect the Mac account, enable disk encryption and treat database backups as credentials. Responses never return stored passwords or tokens. Configuration is checked before commit; credential changes require paused playback and invalidate prior prepared streams. Network exposure is still a separate, explicit operation.

The bootstrap link keeps its code in the URL fragment, then removes it from the address bar when the pairing form opens. Treat it as a secret until consumed or expired. It is not a localhost bypass: possession of the one-use code is required even if a reverse proxy forwards requests over loopback.
